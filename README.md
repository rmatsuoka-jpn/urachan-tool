# うらちゃんツール / urachan-tool

自治体などの閉域イントラネットでも使える、外部通信なしのChromeサイドパネル型業務ツールです。既存システムの改修、サーバー、CDN、ビルド環境を必要としません。

**最新：v0.2.0（実機検証前のデモ版）**。v0.1.1の職場PC更新は確認済みです。

## 主な機能

- **定型文コピー**：検索、「すべて／★ お気に入り／個人／組織共通」の切り替え、個人文の登録・編集・削除、共通文の個人用コピー。お気に入りの★は黄色
- **日付ツール**：今日の日付を西暦／和暦でコピー、西暦年⇔和暦年の表示だけの相互変換、指定日からの暦日加減算と曜日表示
- **機能表示のカスタマイズ**：初期表示は定型文のみ。上部「＋ 機能」から日付ツールを追加・非表示にできます。シンプル／拡張の2モードは廃止しました
- **組織共通データの管理**：配布JSONを確認して取り込み、セット単位で有効・無効、詳細画面で削除。無効なセットはすべての定型文タブから非表示となり、お気に入りやデータは維持されます
- **設定**：機能表示／組織共通データ／バックアップ・復元に分離。説明は「？」から確認可能
- **一括バックアップ**：個人定型文・お気に入り・機能表示設定・共通セットの有効状態をJSONで保存・復元。組織共通本文は別管理
- **開発者メニュー**：設定画面のバージョンを5回クリックすると表示。組織共通JSONの編集・書き出し、任意でこのPCへの反映に対応

## v0.1.x からの更新注意

**v0.2.0は旧版からの自動データ移行を行いません。** 新しい保存領域を使うため、旧版で保存した定型文・お気に入りはv0.2.0に自動で現れません。必要な情報は更新前に別途控えてください。v0.2.0の「バックアップから復元」はv0.2.0形式用で、旧版のJSONはそのまま読み込めません。

拡張機能のIDを保つため、**以前と同じ展開フォルダへファイルを上書き**し、Chromeの `chrome://extensions` で「再読み込み」してください。別フォルダから新規読み込みすると別の拡張機能扱いになる場合があります。

## 配布と導入

配布用ZIPは [GitHub Releases](https://github.com/rmatsuoka-jpn/urachan-tool/releases) から `urachan-tool-v0.2.0.zip` を取得します。GitHubの「Source code (zip)」ではありません。

1. ZIPを解凍し、`manifest.json` のあるフォルダを用意します
2. Chromeで `chrome://extensions` を開き、デベロッパーモードをONにします
3. 新規導入時は「パッケージ化されていない拡張機能を読み込む」でフォルダを選びます。更新時は既存フォルダを上書きして「再読み込み」します
4. ツールバーの拡張機能ボタンからサイドパネルを開きます

配布ZIPは `manifest.json`、`background.js`、`panel.html`、`panel.css`、`panel.js` の5ファイルのみで、設計書やJSONデータは含みません。

Chrome 116以降を対象としています。職場PCの拡張機能インストール・データ持出しに関する規則を守ってください。閉域環境では外部のサービスにアクセスしません。

## 組織共通JSON

配布形式は `format: "urachan-shared"`、`version: 1` のJSONです。架空データの例は [examples/common-sample.json](examples/common-sample.json) を参照してください。

設定 → 組織共通データでJSONを取り込みます。同じセットIDなら既存セットを更新し、**そのセットの有効・無効状態は維持**します。削除時は該当セットの共通お気に入りを解除し、個人用に複製した定型文は残します。

配布JSONの作成・編集は開発者メニューで行い、「JSON書き出し時にこのPCにも反映する」の初期値はOFFです。「このPCに反映」の単独ボタンは引き続き利用できます。

組織共通データの編集は通常画面ではできません。セット内容の編集と配布は開発者メニューから行います。

## プライバシーと保存場所

個人用データは `chrome.storage.local` に保存されます。共有PCの同じChromeプロファイルでは別の利用者にも閲覧される可能性があります。実際の機密・個人情報をテストデータとして保存しないでください。

このリポジトリは**Public**です。住民・職員の個人情報、実在の庁内文書、内部システムURL、認証情報などはコミットしないでください。公開リポジトリはソースコードと架空のテストデータの管理専用です。
