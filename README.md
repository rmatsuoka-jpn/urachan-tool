# うらちゃんツール / urachan-tool

自治体などの**閉域イントラネットで、職員が日常的に使えるChrome拡張**です。既存システムを改修せずに、ブラウザのサイドパネルから定型文をコピーできます。

**現在の状態：v0.1.1 デモ版（v0.1.0の職場PC導入は確認済み、最新版の検証はこれから）**

> まずは1人で使って操作性を検証する段階です。業務用の機密情報・個人情報は試験データとして登録しないでください。

## できること

- **定型文コピー**：一覧の文章をクリックするとコピー。名前・複数行の本文を保存できます
- **画面操作**：右上の「× とじる」でサイドパネルを閉じる。お気に入りの★を黄色で表示
- **検索・4つのタブ**：「すべて」「★ お気に入り」「個人」「組織共通」
- **個人用**：新規登録、編集、削除、削除直後の「元に戻す」
- **組織共通**：JSONファイルの取り込み、同じセットの再取り込みによる置き換え
- **共通文の複製**：組織共通は直接編集せず、個人用にコピーしてから変更
- **バックアップ**：個人用の定型文とお気に入りをJSONで保存・復元
- **シンプル／拡張**：初期はシンプル。設定画面から拡張メニューを表示できます
- **開発者用の隠しメニュー**：共通定型文のセットを作成・編集し、配布用JSONを書き出せます
- **外部通信なし**：サーバー、ログイン、外部CDN、ライブラリのダウンロード、ビルド作業は不要

拡張モードの「便利ツール」は今後追加予定で、現時点では操作できません。

## インストール（配布専用ZIPを使用）

**職場PCへ持ち込む際は、「Code → Download ZIP」ではなく [Releases](https://github.com/rmatsuoka-jpn/urachan-tool/releases) から配布用ZIPを取得してください。**

1. [Releases](https://github.com/rmatsuoka-jpn/urachan-tool/releases) を開く
2. 対象バージョンの **Assets** から **`urachan-tool-v0.1.1.zip`** （以後は最新バージョン）をダウンロードする
3. GitHubが自動表示する **`Source code (zip)` は選ばない**（設計書・テスト等を含むため）
4. 配布用ZIPを**展開**する（ZIPのままでは読み込めません）
5. Chromeでアドレス欄に **`chrome://extensions`** と入力する
6. **デベロッパーモード**をONにする
7. **パッケージ化されていない拡張機能を読み込む** をクリックする
8. 展開したフォルダ（`manifest.json` が直下にある）を選ぶ
9. Chromeのツールバーで「うらちゃんツール」をクリックしてサイドパネルを開く

配布ZIPには `manifest.json`、`background.js`、`panel.html`、`panel.css`、`panel.js` の**5ファイルだけ**を入れます。組織共通JSONのサンプル、設計書、テスト、READMEは含みません。

Chrome 116以上を対象としています。職場PCの管理ポリシーに従ってください。ローカル読み込みは利用者の職場PCで確認済みですが、**更新・再読み込みはまだ実機で確認できていません**。

## まず試す操作

1. 「＋ 新しく登録」で名前とコピーする文章を保存する
2. 一覧に戻り、登録した文章をクリックする
3. Word・メール・イントラの入力欄などに `Ctrl + V` で貼り付ける
4. ★でお気に入りに登録し、タブで絞り込む
5. 共通データを試す場合は、設定画面のバージョン表示を5回クリックして**開発者モード**を有効化し、架空データで共通JSONを作成・書き出してから、設定画面で取り込む（サンプルJSONは配布ZIPに含まれません）
6. 共通文の「複製」で個人用にコピーする
7. 必要に応じて「バックアップを保存」で個人用データをファイルに退避する

**保存場所**：登録データはChromeの `chrome.storage.local` に保存します。拡張機能を削除したりChromeプロファイルを変更したりするとデータが引き継がれないため、事前にバックアップしてください。

## 組織共通JSONを作成する

普段の利用画面では共通定型文は編集できません。**配布用ファイルの作成・編集は隠しメニュー**にまとめています。

1. 「設定」を開く
2. 設定画面の最下部にある **「うらちゃんツール v0.1.1」** を5回連続でクリック
3. 表示された「開発者用メニュー」で **「共通JSONを作成・編集」** を選ぶ
4. 「新しいセットを作成」して定型文を登録するか、既存の共通セット／JSONを読み込む
5. **「JSONを書き出す」** を押す（このPCの共通定型文にも反映されます）
6. 配布したJSONを他のPCで「設定 → 共通定型文を取り込む」から読み込む

設定画面から開発者モードを終了できます。隠し操作はUIの簡素化が目的であり、**セキュリティ上の認可・権限制御ではありません**。

## データ仕様

共通ファイルは `format: "urachan-shared"` と `version: 1` を持つJSONです。サンプルは [examples/common-sample.json](examples/common-sample.json) を参照してください。

- セットの `id` が同じなら、再取り込みで古い共通定型文を置き換えます
- 個人用データは共通JSONの取り込みでは変更しません
- 同じ共通文のIDを維持していれば、お気に入りの指定も保持されます
- 削除された共通文のお気に入り指定は自動的に整理されます
- JSONのサイズは1MB以下。本文は1件最大10,000文字、1セット最大500件

個人バックアップは共通JSONとは**異なる形式**です。取り込み画面で混同しないようにチェックしています。

## Releasesへの自動配布

[`.github/workflows/release-extension.yml`](.github/workflows/release-extension.yml) が、`main` ブランチへの拡張ソースの更新や、Actionsからの手動実行で動きます。

- JavaScript構文とNode.jsテストに合格した場合だけ、**指定した5ファイルだけ**をZIP化します
- ZIP内のファイル一覧を照合し、余計なファイルが混ざれば失敗します
- `manifest.json` のバージョンに基づき `v0.1.0` などのGitHub Releaseを作成し、ZIPとSHA-256チェックサムを添付します
- **同じバージョンのReleaseが既にある場合は上書きしません**。新しい配布ZIPが必要になったら、`manifest.json` のバージョンを上げてコミットしてください
- GitHub Actionsの権限設定でRelease公開が許可されていない場合は、ジョブのエラーを確認してください

**注意：** `main` の最新ソースと公開済みReleaseが異なる場合があります。職場PCに持ち込むものはReleaseのバージョンを基準にしてください。

## 開発・検証

依存パッケージやビルドはありません。ソースを更新するときは、通常は拡張機能の再読み込みで変更を反映します（職場PCでの動作は未検証）。

Node.jsがある開発環境では、データ処理テストを次のコマンドで実行できます。

```sh
node --test tests/panel.test.mjs
```

デモ確認のチェックリストは [docs/demo-test.md](docs/demo-test.md) です。

## 公開リポジトリの注意事項

このリポジトリは**Public**です。住民情報、職員の個人情報、実際の業務文書、認証情報、内部システムURLや内部構成情報などはコミットしないでください。テストは架空データを使用します。

GitHubは**ソースコードの管理用**であり、閉域ネットワーク内の端末がGitHubへアクセスする必要はありません。ファイルの移送・配布方法は所属組織のルールに従います。
