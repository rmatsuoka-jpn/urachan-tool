# 開発ロードマップ

> 2026-11-10時点の計画。進捗管理はこのファイルとGitHub Issuesを使うことを想定しています。**ここにある項目は実装済みを意味しません。**

## 運用・判断の優先順位

1. 説明書を読まなくても使えること
2. 外部通信を必要としないこと
3. 利用者の定型文データを保護すること
4. 組織共通データの更新を安全・簡単に行えること
5. 将来の拡張性を確保すること

詳細仕様は [基本設計書](design.md) を正とします。

## Phase 0：実現条件の確認（未着手）

- [ ] 対象Chromeのバージョン・組織の管理ポリシーを確認
- [ ] サイドパネル、ローカル保存、コピー機能の実装可否を検証
- [ ] 拡張機能の試験導入と本番配布の方式を整理
- [ ] 必要権限の最小構成を決定
- [ ] 公開リポジトリへ機密情報を含めないルールを確認

**完了条件：** 配布方針が未決でも、許可された開発・検証環境で安全に試作できる状態になっている。

## Phase 1：定型文コピーの最小試作品（未着手）

- [ ] Manifest V3 / Side Panel APIの雛形を作成
- [ ] 初期状態はシンプルモードにする
- [ ] 個人用定型文の登録・編集・削除を実装
- [ ] 行クリックでコピー・結果表示
- [ ] すべて／お気に入り／個人／共通のタブ
- [ ] お気に入りの登録・解除
- [ ] 登録名と本文の検索
- [ ] コピーや★操作の誤反応を防ぐ
- [ ] 空状態・エラー表示を分かりやすくする
- [ ] 拡張モード切替と基本メニュー枠

**完了条件：** 初見の利用者が説明なしで定型文を登録し、コピーして他の画面に貼り付けられる。

## Phase 2：組織共通・JSON入出力（未着手）

- [ ] 組織共通JSONのスキーマと検証処理
- [ ] 共通JSONの手動取り込み・再取り込み
- [ ] 同じセットの再取り込み時に重複させない
- [ ] 共通定型文を直接編集不可にする
- [ ] 共通文を「個人用にコピー」して編集する
- [ ] 個人用定型文・お気に入り情報のバックアップ／復元
- [ ] 取込失敗時に既存データを保持
- [ ] 設定／管理画面と、短い日本語の結果表示

**完了条件：** 共通文を更新しても個人用データが失われず、取り込み・移行を説明書なしで行える。

## Phase 3：現場検証・配布準備（未着手）

- [ ] 説明なしの操作テスト
- [ ] 実際のサイドパネル幅での視認性確認
- [ ] Chrome再起動・PC交換・再取り込み・異常ファイルの確認
- [ ] 共用PCを想定した注意事項の確認（個人PCを基本とする）
- [ ] 実際の管理対象端末で配布・更新手順を検証
- [ ] 利用者から問い合わせが出やすい箇所を改善

**完了条件：** 小規模利用の手順、既知の制約、サポート方針が整っている。

## Phase 4：拡張モードの便利機能（将来・未着手）

機能追加は個別に優先度・権限・運用負担を評価します。

- [ ] 文字変換（全角半角、空白・改行整形等）
- [ ] 日付変換（和暦／西暦等）
- [ ] 便利リンク／各種ユーティリティ
- [ ] 業務別の支援機能（必要性と権限を別途検討）

**留意：** 追加機能は原則として拡張モードに集約し、シンプルモードの日常操作を複雑にしない。
